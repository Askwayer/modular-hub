# AI 网关人工验收里程碑

版本：0.1 草案 · 日期：2026-11-13。**所有关口均待验收；没有已完成的实现、压测或试点结论。**

本清单专门标出用户人工介入点。各次验收以 [PRD](02-prd.md) 和冻结的测试条件为准，不以截图好看、能够启动或一次请求成功替代完整证据。

## M0：需求与架构确认

人工阅读 [项目评估](01-project-assessment.md)、[PRD](02-prd.md) 和 [迭代计划](03-iteration-plan.md)。

- [ ] 确认独立 Java 非阻塞网关和统一仓库方案；理解尚无 Java/FastAPI 性能实测胜负。
- [ ] 确认一个课题一个逻辑 Key；公司识别采用可信部署身份，明确 mTLS 终止位置及发行/撤销责任人。
- [ ] 确认课题、公司 A、候选公司 B、公司编码来源和权限角色。
- [ ] 提供实际模型版本/能力清单和可测试环境；确认 C0 由 M1 标定。
- [ ] 确认 NFR 建议值、保留期、轮换窗口、离线策略、未知 usage 和事件丢失窗口的处理原则。
- [ ] 确认首版不含严格计费、复杂工作流和文件预处理；界面在核心转发验证后建设。

**通过条件：**以上事项形成明确记录，未决项有负责人且不阻塞 I1。证据：签字版文档、决策表、测试资源清单。当前状态：待验收。

## M2：可信授权与模型健康

| 编号 | 人工操作/演示 | 必须看到的结果 |
| --- | --- | --- |
| AC-20 | 用有效/失效 Key、已授权/未授权部署、伪造公司头分别请求；多实例撤销 | 身份及公司不匹配均拒绝；跨公司越权为 0；新请求撤销 ≤5 秒；查询范围同样受限 |
| AC-21 | 为课题配置模型白名单与别名，轮换 Key；查询模型列表并指定未授权模型 | 只看见和调用获准模型；命中端点可追溯；轮换到期旧 Key 失效；原始模型凭据不外泄 |
| AC-22 | 模拟端点不可达、认证失败、列表正常但推理失败，再恢复；模拟无流量和数据过期 | 分层状态正确，未知不显示健康；故障原因不混淆；发现/恢复符合冻结预算 |

**证据包：**授权矩阵、请求及拒绝样本、公司 ID 来源、证书/Key 生命周期说明、撤销传播测量、健康事件时间线、策略回滚记录。

**通过条件：**鉴权、公司归属和健康语义全部正确；不得以“内网可信”为由跳过伪造身份测试。此关口通过不等于允许生产流量。

**通过条件：**无未解决的越权、无界资源、协议破坏或静默丢记录问题；数据缺口明确展示。人工接受恢复边界后才进入真实业务试点。
