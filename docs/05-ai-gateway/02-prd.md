# 企业 AI 网关 PRD

版本：0.1 草案 · 日期：2026-11-13 · 产品状态：待 M0 人工验收。

本文是需求基线，包含待验收的建议值；不是已实现说明、性能报告或上线承诺。技术选择依据见 [项目评估](01-project-assessment.md)，人工关口见 [验收清单](04-acceptance-checklist.md)。

## 1. 背景与目标

集团约有 8 家分公司，多个 FastAPI 业务服务使用相近的公共模型调用代码。随着同一课题推广到多家公司，直接分散调用模型使调用归属、用量汇总、并发控制和模型故障定位变得困难。

建设统一 AI 网关，让业务服务通过课题凭据访问公司本地模型，同时记录可信的公司归属。第一优先级是低开销转发、模型健康检测和持续稳定运行；统计服务于容量规划和故障定位，首版不承诺财务级精确计费。

成功标准：真实业务能按配置接入；正常流式响应无明显额外延迟；过载时有界拒绝而非资源耗尽；能够区分模型不可达、模型无法推理和业务侧错误；同一课题跨公司推广后仍能准确授权和分组观察。

## 2. 范围与版本

| 范围 | 首版 P0 | 后续 P1/P2 |
| --- | --- | --- |
| 模型调用 | `/v1/chat/completions` 非流式和 SSE；授权后的 `/v1/models` | embeddings、rerank、音频、Responses 等逐项评估，不默认兼容 |
| 授权 | 课题申请、一个逻辑 Key、公司推广授权、可信部署身份、模型白名单 | 更细的组织策略、企业身份自动对接 |
| 性能稳定性 | 连接池、有界资源、超时取消、分布式并发限制、故障隔离、优雅停机 | 基于实测需求的复杂调度、多地域能力 |
| 健康度 | 被动错误观测、轻量探测、低频实际推理、状态与告警事件 | 与现有告警平台深入集成、更多服务类型 |
| 统计 | 请求、Token、字节、并发、错误、延迟；缺失 usage 明确标识 | 严格 Token 预算、费用归集、复杂预测 |
| 管理 | 最小课题/模型/授权/健康/用量页面，延后到转发验证之后 | 更复杂审批、个性化报表 |

不纳入首版：模型训练与部署平台、GPU 调度器、提示词管理平台、业务工作流、文件存储/OCR/PDF 预处理、响应缓存、自动切换到语义不同的模型。保留项目国际化方向，不能因本专题删除既有国际化配置。

## 3. 用户、权限与业务流程

| 角色 | 主要操作 | 数据范围 |
| --- | --- | --- |
| 平台管理员 | 管理模型端点、凭据、系统配置和部署登记 | 经明确授权的集团范围；敏感操作审计 |
| 课题负责人 | 申请课题、申请公司推广、查看授权范围内用量、申请轮换 Key | 所负责课题及获准公司 |
| 公司管理员 | 登记本公司部署、查看健康与用量、停用本公司部署 | 本公司及显式授予的其他公司 |
| 运维人员 | 查看健康、性能、告警、发布和回滚 | 运维授权范围；默认不查看业务正文或 Key |
| 机器调用方 | 调用获准模型 | 课题、公司、环境、部署身份授权的交集 |

正常流程：申请课题 → 管理员审批及模型授权 → 生成并交付课题 Key → 授权试点公司 → 登记部署并发放部署身份 → 验证接入 → 查看试点数据 → 授权下一家公司 → 逐步推广。

采用简单申请状态和操作审计，不重新引入已移除的 `vita-workflow`。课题状态建议为草稿、待审批、启用、暂停、关闭；公司授权和部署状态各自独立。暂停公司 A 不得影响同课题公司 B；暂停整个课题则禁止所有公司新请求。

## 4. 功能需求

### FR-01 课题及推广管理

课题至少包含唯一编码、名称、负责人、用途、允许模型、状态和有效期。公司推广关系记录课题、公司、环境、启停状态、生效期、并发/RPM 配额与审批记录。关闭或暂停后保留历史统计与审计，不通过物理删除清空历史。

申请与审批权限分离；审批时明确模型和公司范围，不能依赖调用方自行声明。首版用人工审批实现业务闭环，后续可接统一流程系统。

### FR-02 课题 Key 生命周期

一个课题拥有一个逻辑 API Key。不同模型、不同公司使用该课题的授权关系，不擅自改成“每家公司一个课题 Key”。生产与测试由部署身份区分和控制，避免测试请求计入生产统计。

Key 由安全随机值生成，明文只在创建/轮换时展示一次；数据库保存不可逆校验值与非敏感前缀，禁止列表返回完整 Key。支持启停、有效期、轮换和泄漏处置；轮换期间最多两个有效版本，重叠窗口上限建议 24 小时，M0 确认。服务端原始模型 Key 单独保管，永不返回给业务调用方。

Key 吊销对新请求的生效目标见 NFR-04；普通轮换允许已准入的请求按原超时结束，紧急撤销可明确选择中止现存流。整课题 Key 泄漏需要整课题轮换，不能承诺仅撤销一家公司就彻底解决。

### FR-03 可信公司与部署身份

**课题 Key 只能证明课题，不能证明公司。** 推荐每个部署使用绑定公司、环境、有效期的客户端证书（mTLS），并登记其允许使用的课题。一个部署可获准多个课题，但一个部署身份只绑定一个公司和环境；跨公司业务通过不同受控身份调用。

若 mTLS 在受控入口终止，入口必须删除外部伪造身份头，验证证书后写入可信身份，并通过受限的认证链路连接网关；业务方不能绕过入口直接访问网关。M0 确定使用网关直验还是受控入口，不将普通 `X-Company-ID` 当作可信身份。

每次请求校验 Key、课题状态、部署身份、公司推广授权、模型权限和环境。任一缺失或不匹配均拒绝；调用方填写的公司、模块、实例标签不能扩大权限。模块/实例标签若未登记或无法验证，在页面标识为调用方声明值。

公司 ID 来自经管理员核准的集团公司名录。集团组织服务未就绪时，首版使用受控的 8 家公司编码映射，维护来源、版本和操作记录；后续对接保持 ID 稳定。部门 ID、公司 ID、数据库公共 `tenant_id` 不得未经设计直接等同。

### FR-04 模型注册与授权路由

维护逻辑模型名、真实模型名、端点、协议能力、超时、连接/并发上限、健康策略和上游凭据引用。`fast/strong` 可以作为课题内别名，但必须显式映射，记录实际命中的模型及端点。

仅管理员可配置白名单地址；请求不得指定任意上游 URL。授权模型列表取课题、公司、部署许可交集。多副本只在已批准的等价模型端点间选择；首版不自动跨模型降级，不接受透传的上游鉴权头覆盖服务端凭据。

### FR-05 OpenAI 兼容转发

| 接口 | 行为 |
| --- | --- |
| `POST /v1/chat/completions` | 支持普通 JSON 和 `stream=true`；返回兼容的响应体或 SSE |
| `GET /v1/models` | 仅返回调用主体已获准的逻辑模型，不暴露隐藏端点或凭据 |
| 管理 API | 沿用 Vita 管理认证、权限、分页及 `CommonResult<T>` |
| 运维健康/指标 | 内部受控访问；不借此公开模型凭据或未经授权的全局信息 |

外部 `/v1/*` 采用上游兼容契约，不能包装成平台统一响应。保留支持范围内的 `choices`、`usage`、`finish_reason`、工具调用、扩展字段及流式终止语义；不能简化为首条文本。以实际模型能力表声明支持项，未知可透传字段不得被无意删除。

请求中的原生图片内容可在大小限制内透传，但不在网关下载、渲染或 OCR 业务文件。请求体、单个 SSE 事件和缓冲均有上限；超限返回明确错误，数值在 M1 根据实际负载冻结。设置连接、等待首个有效输出、流空闲和总时长超时，不能只有一个无限等待的读取超时。

生成网关请求 ID 并关联上游请求 ID；调用方业务追踪 ID 另存且校验长度，不能用它替代幂等内部主键。只转发白名单请求头，移除 hop-by-hop 头和任何会泄漏凭据的信息。协议外请求返回明确不支持，不伪装成功。

### FR-06 流式转发与资源回收

复用长生命周期连接池，逐段转发 SSE，不等待整段生成完毕。缓冲有界，慢客户端通过背压控制读取；不能无限攒积响应。使用字节块时正确释放缓冲，解析 usage 只保留有界状态，不能为统计累积完整文本。

客户端断连、网关超时、上游失败和停机都必须触发清理：停止读取、取消/关闭上游、结束生命周期、释放或进入待回收的并发租约。一次请求只结束一次，不能重复扣减。网关取消不保证上游 GPU 已立即停止计算，应实测上游行为并避免立即重试放大负载。

首版网关自动重试为 0；接入试点时关闭 SDK 的隐式传输重试并盘点业务重试。输出已经开始后不能透明重试或替换模型；如果未来开放重试，须单独评估幂等性、尝试次数和计量。

### FR-07 并发、流量与过载控制

按网关、模型服务、课题和课题×公司设置有界准入；实际限制取交集，多个网关实例共同执行，不能仅靠进程内 Semaphore。RPM 限制和活跃请求限制分开；首版优先快速拒绝，不建立无界排队。返回 429 时标识限流来源并在可计算时提供重试提示。

分布式租约具有唯一持有者、TTL、续租和幂等释放；进程崩溃后能过期回收。续租失败应停止接收新请求并终止受影响调用，不能在失去租约后无限运行。租约 TTL、续租周期和恢复时限在 M3 通过故障测试确定。

网关在途请求数不是模型实际 GPU 执行并发数：上游可能排队或动态批处理。严格 GPU 容量约束需要上游共同控制，网关只能保证其准入语义。Token 首版统计和告警，不在 usage 不完整时冒充严格的硬预算控制。

### FR-08 分层健康检测

| 层次 | 检测内容 | 能证明什么 |
| --- | --- | --- |
| 网关存活 | 进程及事件循环是否响应 | 网关仍在运行，不代表依赖均健康 |
| 网关就绪 | 有有效策略、准入依赖可用、可接新请求 | 可承接流量；不因所有模型故障反复重启网关 |
| 上游可达/协议 | 受支持的健康接口或低成本模型列表探测 | 网络、认证和协议可用，不能证明能够生成 |
| 上游实际推理 | 低频固定短输入、有限输出的合成调用 | 指定模型在该时刻实际可生成 |
| 被动观测 | 真实流量的失败、超时、首输出与总耗时 | 用户体验和负载变化，需区分业务输入问题 |

健康状态为未知、健康、降级、不可用；展示分层结果、最后成功时间、失败原因和数据时效。无样本、探测过期或被禁用不能显示健康。轻量探测建议每 10 秒一次，连续 3 次失败标记不可用、连续 2 次成功恢复；推理探测建议每 60 秒一次且最多输出 8 个 Token。均为 M0/M1 待确认默认值，不是所有模型通用常量。

多实例通过选主或分片避免重复探测；有独立的连接/并发预算。实际推理探测也遵守模型容量上限，过载时可跳过并显示结果过期，不能为探测挤占无界生产资源。探测 Token 与业务 Token 单独统计。

客户端参数错误、课题拒绝和网关限流不触发模型故障。上游凭据失效、连接错误、5xx、推理超时分别归因；上游 429 标为容量压力。熔断按端点且有半开恢复，不因一个调用者错误封禁全部模型。

### FR-09 用量与性能统计

维度至少包括时间、课题、公司、部署、环境、逻辑/实际模型和端点，业务模块标签为可选。保存请求与上游尝试的关联，区分拒绝、成功、上游失败、网关失败、取消和超时。

| 指标 | 口径 |
| --- | --- |
| 请求数 | 收到数、鉴权拒绝数、准入数、成功/失败/取消数分别统计 |
| Token | 上游报告的输入、输出和总量；区分已知、缺失、估算，不把缺失当作 0 |
| 流量 | 网关观测的请求/响应应用层字节数；明确不等于 TLS 或网卡总流量 |
| 并发 | 逻辑在途请求和有效准入租约数；上游实际排队/运行量另列 |
| 延迟 | 接收至首个有效模型输出、接收至结束、上游阶段耗时；普通首字节另列 |
| 错误率 | 分来源、状态和原因；业务参数错误不混入网关自身故障率 |

SSE usage 可能在末尾才出现。客户端取消、上游不支持或断流时标为未知；累计 usage 取最终值或最大有效快照，不把每帧累计值相加。SSE 帧数不等于 Token 数。一次业务任务多次调用模型是多条模型请求，不能因业务 trace 相同就错误去重。

保存分钟/小时聚合以支撑查询；高基数的 request ID、完整实例标签和凭据不得作为时序指标标签。正常看板数据新鲜度目标为 60 秒，必须显示最后更新时间和采集缺口。

### FR-10 用量事件可靠性

请求生命周期产生开始/结束事件，带稳定 event ID、request ID、attempt ID 和策略版本。消费端幂等更新，不因重放重复累计；记录已开始但无可靠结束的请求为结果未知。

正常转发不等待 MySQL 插入。采用有界队列、独立写入资源和可重放持久暂存，禁止队列满静默丢弃。积压超过阈值告警，达到容量上限时拒绝新的模型请求，不能无限占用内存或磁盘。恢复后补写并核对。

首版是运营监测，不保证突然掉电前尚未持久化的内存事件零丢失。必须在 M3 记录实测丢失窗口、将异常退出时段标为数据可能不完整，并在看板展示缺口。已确认持久化事件必须能够重放且不重复；若要求全量零丢失，应另立版本引入入站持久确认并重新压测延迟，不能同时许诺零等待。

### FR-11 看板与查询

最小管理页面包括：课题及申请详情、公司推广与部署、Key 状态与轮换、模型及健康详情、用量查询、系统告警。先实现必要操作和故障定位，再扩展复杂报表。

用量页支持时间区间、课题、公司、多模型、环境、状态筛选；KPI 展示请求数、已知 Token、未知 usage 比例、并发峰值和错误率。请求详情展示阶段耗时、状态原因、归属和追踪 ID，不展示提示词、回答全文及凭据。

列表、合计、详情、导出都执行同样的数据权限；前端隐藏按钮不替代后端校验。页面沿用 `web-ele` 与现有国际化机制，不新增另一套前端框架。

### FR-12 告警与诊断

对模型不可用/恢复、错误率或延迟超阈值、并发占用、采集积压、磁盘水位、策略过期、凭据到期产生结构化事件。首版交付管理页和受控日志/指标查询；通知渠道接入需要另行配置，不在本轮主动发送外部消息。

事件具有去重键、首次/最近时间、级别、受影响端点/公司范围和恢复状态；短暂抖动通过阈值抑制，连续故障不能每次探测重复刷屏。诊断能关联上游失败与网关请求，但不泄漏业务内容。

### FR-13 管理权限、审计与数据保护

管理登录复用 Vita；机器调用不走员工 Session。管理权限至少分查看、申请、审批、配置、Key 轮换、部署停用和导出，公司数据范围在服务端求交。集团查看也需要显式授权，不能默认所有登录员工可看全集团。

审计记录操作者、对象、公司范围、动作、前后非敏感配置、时间和结果。默认不存提示词、回答、图片、Authorization 头、完整 Key；排错使用合成数据。上游密钥加密保存或使用受控秘密引用，主密钥位于外部配置；传输使用受控加密链路。

时间按 UTC 存储，界面按用户时区显示。建议请求明细 30 天、聚合 180 天、管理审计 180 天，M0 由业务确认；支持按策略清理和审计，长期统计不依赖永远保留明细。

### FR-14 配置、部署与回滚

转发应用独立可执行 JAR，依赖随包交付；配置和证书外置。管理策略有版本、发布时间、校验和及生效状态，发布失败不替换上一个完整有效版本。限制和凭据状态通过可信策略/准入存储检查，不在事件循环调用阻塞 JDBC。

管理页面故障时，在有效策略和准入存储可用的前提下继续转发。建议策略最大离线有效期为 24 小时；超过后拒绝新请求，M0 确认。该离线策略不能覆盖 Key 撤销校验：撤销通道异常时按 FR-16 保守拒绝。

交付包含制品校验、版本与依赖清单、环境配置模板、健康验证、优雅停止、日志轮转、升级/回滚手册和数据库变更方案。新增表的 DDL、代码生成和管理 CRUD 遵守现有后端规范，具体表结构在实现阶段单独设计。

### FR-15 业务接入迁移

试点选一个课题、一个公司、一个真实部署。先以合成请求验证，再切小部分实际业务。业务侧保留提示词、文件处理和已有领域接口；主要调整模型地址、课题 Key、部署身份、超时及重试配置。

同进程多课题使用不可变的调用上下文或分别绑定的客户端，不能在并发请求间修改共享客户端默认 Key。每条直接调用模型的代码路径均须纳入清单，不能只替换公共 HTTP 路由。

回滚通过受控配置将试点切回原上游；保留短期原接入配置并审计回滚，明确该时段无法获得完整网关统计。正式推广后根据验收决定是否收回业务端原始模型凭据，禁止长期保留无人管理的绕行入口。本轮不修改参考目录。

### FR-16 明确的故障行为

| 故障 | 对新请求 | 对在途请求和统计 |
| --- | --- | --- |
| Key、公司或模型未授权 | 401/403，不能请求上游 | 记录脱敏拒绝原因 |
| 配额/并发满 | 429，不无限排队 | 原请求按正常生命周期完成 |
| Redis/准入或撤销校验不可用 | 503，不能绕过授权/配额 | 续租失败按 FR-07 终止；状态不确定显式记录 |
| MySQL 暂时不可用 | 暂存容量允许时继续；满后 503 | 已接受事件持久暂存、重放；故障期间看板显示延迟 |
| 管理服务不可用 | 有效策略及准入依赖正常时继续 | 不影响已经转发的流；超过策略有效期拒绝新请求 |
| 模型端点不可用 | 选获准的健康等价端点，否则 503 | 已输出的流不得透明重放；记录实际失败 |
| 上游报错 | 对兼容错误保留合理状态/结构，清除敏感字段 | 不中途伪造成功或完整 usage |
| 上游连接失败/超时 | 尚未提交响应时 502/504 | 已开始 SSE 则按协议能力报告失败或断流，不伪造成功终止标记 |
| 客户端断开 | 不再产生后续输出 | 取消上游，清理租约；缺少 usage 标未知 |
| 网关滚动重启 | 先撤销就绪、停止新流量 | 有界排空；超时仍未完成的流失败并留痕，不能保证无损迁移 SSE |

## 5. 概念数据模型

| 对象 | 关键关系及约束 |
| --- | --- |
| Topic / TopicKey | 课题与 Key 版本；一个逻辑凭据、有限轮换窗口 |
| CompanyReference | 稳定公司标识及权威来源，不替代完整集团组织架构 |
| TopicCompanyGrant | 课题×公司×环境的授权、状态及配额 |
| DeploymentIdentity | 绑定公司和环境，关联允许课题及凭据版本 |
| ModelService / ModelEndpoint | 逻辑模型、实际端点、能力和凭据引用 |
| TopicModelGrant | 模型许可与别名路由；与公司/部署许可求交 |
| Request / Attempt / UsageEvent | 逻辑请求、上游尝试、事件的独立标识和最终状态 |
| UsageAggregate | 按时间、课题、公司、环境、模型聚合的运营用量 |
| HealthSample / Alert / AdminAudit | 健康样本、状态事件和管理操作审计 |

所有统计记录保存服务端解析的公司和课题，不信任正文中的对应值。字段、索引、唯一约束、租户语义、归档和迁移脚本在 M2/M3 技术设计中明确，本 PRD 不直接充当生产 DDL。

## 6. 非功能指标与验证方法

以下为**建议门槛，尚未测量**。M0 确认业务目标，M1 冻结目标硬件、模型版本、负载和容量 C0；不在验收失败后偷偷放宽。

| 编号 | 目标 | 测量条件 |
| --- | --- | --- |
| NFR-01 延迟与吞吐 | 额外首个有效输出延迟 p95 ≤20 ms、p99 ≤50 ms；成功吞吐 ≥直连的 95% | 相同网络、TLS条件、输入/输出、重试和负载；在模型及网关均未饱和的 C0 内测量 |
| NFR-02 有界资源 | 无 OOM、死锁、无界队列；排空后连接/租约回落，堆/直接内存/FD 无持续增长 | M3 持续 24 小时、M6 持续 72 小时；记录 GC 后基线和资源平台期，不能只看 RSS |
| NFR-03 故障与可用性 | 正常负载下网关自身故障率 ≤0.1%；满足过载拒绝和故障矩阵 | 排除已单列的上游/客户端错误但保留完整总数；故障注入验证双实例恢复 |
| NFR-04 身份与撤销 | 跨公司越权为 0；Key/公司/部署撤销对新请求 ≤5 秒生效 | 多实例、并发和缓存更新测试；撤销链路故障时保守拒绝 |
| NFR-05 健康与监测 | 轻量探测故障发现 ≤30 秒、推理故障发现 ≤180 秒、健康就绪查询 p95 ≤100 ms | 探测调度和超时预算计入；生产负载下验证，探测被限额时显示未知/过期 |
| NFR-06 用量一致性 | 完整 usage 样本与上游一致，重放不重复；缺失率可见；正常刷新 ≤60 秒 | 流式/非流式、累计 usage、断流、DB 中断、事件重放和进程崩溃 |
| NFR-07 交付与恢复 | 目标环境无需在线解析依赖；可独立启停、回滚、备份恢复 | 在目标等效环境执行 JAR 启动、证书更新和恢复演练，记录实际恢复时间 |

NFR-05 不是“每个故障必在 30 秒内识别”。例如三次失败探测还要包含超时，M1 必须调整周期或超时使总预算符合目标；无样本时不伪造满足指标。恢复时间同样取决于成功阈值和探测间隔，建议上限 180 秒并由 M1 验证。

### 性能基线方法

先使用可控模拟上游验证代理开销，覆盖并发 1/10/50/100、固定和抖动首输出、不同流长度、慢读和断连；模型真实容量不足时不能把上述并发直接施加给生产模型。

再用指定真实模型测得未饱和容量 C0，在相同硬件资源预算下交替执行直连与网关路径，预热后至少三轮。记录 p50/p95/p99、成功吞吐、CPU、堆/直接内存、GC、连接、事件循环延迟和上游排队。合成上游报告与真实模型报告分开，不从混杂的端到端模型耗时中直接推断代理开销。

M1 若需要验证 Java 相对 FastAPI 的优劣，再实现**等价的最小 FastAPI 代理基线**：相同协议、统计/鉴权开关、连接池、资源限制、worker 合计 CPU/内存和负载，使用相同测试矩阵。不把原有完整业务服务当成 Python 代理基准，不为此改动参考项目。未执行这组对照之前，仅报告“Java 达标/未达标”，不报告“比 FastAPI 快多少”。

M1 先验证基本转发，M3 必须打开完整鉴权、分布式限流、统计及探测后重测；不能用空壳代理数字代表最终产品。测试结果保存原始数据、环境清单、制品版本和复现方式。

## 7. 依赖、风险和待决事项

M0 需要确认：试点课题/公司、权威公司编码、mTLS 终止位置、实际模型服务清单与协议能力、目标容量及硬件、数据保留期、Key 轮换/策略离线窗口、上线冗余拓扑。未确认前可以完成文档和可撤销的准备，不假定生产已经具备这些条件。

主要风险是身份被伪造、单点集中故障、流式资源泄漏、统计不完整、SDK 重试放大和上游协议不一致。对策与验收分别落在 FR-03/06/07/08/10/16，而不是依赖 Java 语言本身保证。

月度可用性目标需结合实际部署与依赖冗余另行确认；72 小时测试不能证明全年可用性。首版不写无依据的“无限并发”“零性能损耗”“100% Token 准确”承诺。
