# 项目决策与版本范围

[返回导航](README.md)

## 一句话方向

Modular Hub = **统一门户 + 平台核心 + 独立业务应用 + 统一接入规范**。

平台核心采用模块化单体；部门业务未来独立进程、独立前端、独立数据边界。初期不需要 Spring Cloud、Nacos、Kubernetes 或微前端运行时。

## 当前已经有什么

- 后端：be-vita，保留认证、用户部门、角色权限、菜单、审计、文件、验证码和代码生成基础；工作流、报销及 App 用户体系已裁剪，新增四个部门业务应用骨架。
- 前端：Vben 5.7.0 的 `web-ele`，已经做过部分 be-vita 登录与 API 适配。
- 前后端与跨工程文档已于 2026-11-13 合并为统一 Git 仓库，原提交历史保留，见 [Git 管理说明](git-management.md)。应用构建、部署边界仍分别管理。
- 代码值得保留，无须立即重写；安全、接口契约和交付闭环需要先补齐。

## 已推荐的核心决策

| 问题 | 当前推荐 |
| --- | --- |
| V0.1 后端 | 保留现有模块名称与结构，以 `vita-admin` 为唯一交付入口 |
| 是否新增七个 hub 模块 | 不新增；先通过包和公开服务接口划分职责 |
| V0.1 认证 | 保留 Sa-Token，修正密码、会话与授权 |
| OIDC | V0.2 独立应用接入前再确定；不自建完整授权服务器 |
| 权限缓存 | V0.1 不跨请求缓存 RBAC，同一请求内复用快照 |
| 前端 | Vben 用作平台门户；固定后端菜单模式，适配在应用层完成 |
| 数据库 | 保留 IAM 表，建立版本迁移；不重复建 hub_user 等实体 |
| 应用注册 | V0.1 只设计 Manifest，不建注册表和探测调度 |
| 演示场景 | 当前身份与权限只读页，不新增业务表 |
| 基础部署 | Nginx + 单实例后台 + MySQL/Redis；Compose 可作重复部署载体 |
| IAM 写操作 | 推荐 V0.1 仅超级管理员可写，是否接受待用户确认 |

## 四个版本各自验证什么

| 版本 | 主要结果 | 不应提前承诺 |
| --- | --- | --- |
| V0.1 | 安全登录、IAM、动态菜单、演示、迁移、测试与平台部署闭环 | 跨应用 SSO、独立业务接入 |
| V0.2 | 第一个真正独立的业务进程、前端与数据库通过契约接入 | 自动容器编排、复杂应用市场 |
| V0.3 | A 独立构建发布，不要求重启 B；有发布记录和恢复方案 | 默认零停机 |
| V1.0 | 接入契约、模板、测试、监控、安全和恢复流程可持续使用 | 单机架构具备机器级高可用 |

## 暂时不用消化的内容

完整微前端、Design System 全面拆包、AI Agent 平台、服务网格、分布式事务、多租户 SaaS 和自研 OIDC 服务器都不进入 V0.1。
