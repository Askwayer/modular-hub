# be-vita Java 约定

## 规则入口

先读取 `AICoding/rules/be-vita-ai-codegen-rules.md` 的“3.1 模块边界”至“3.6 事务、校验与异常”、“3.9 核心业务代码中文注释”、“5. 明确禁止”、“7. 模块专项规则”、“8. 交付检查清单”和“全局约束”。本 Skill 只编排执行过程。

## 工作流

1. 检查分支状态、目标模块目录、依赖关系、同类实现和相关测试，先用精确类名或方法名定位，再读取必要源码片段。
2. 确定变更所属层次，保持 Controller、Service、Mapper、Entity、DTO、VO 和配置类职责，不跨模块访问内部实现。
3. 沿用目标文件的导入、注解和空行风格；源码使用 UTF-8 和 4 空格缩进。不得因局部修改批量格式化无关代码，也不得自行引入新的格式化工具。
4. 对照主规则检查类型与后缀命名、统一返回和分页对象、事务入口、参数校验、异常语义及持久化边界。
5. 仅在关键业务规则、事务边界、状态流转、并发控制、外部集成和重要异常原因处增加中文注释，不机械解释直白代码。
6. 优先运行受影响模块的编译和测试，并检查差异中是否包含无关格式变化、越层调用或第二套基础对象。

## 组合与交付

- 涉及表结构或 Entity 字段映射时，继续读取 `AICoding/skills/be-vita-database-design/SKILL.md`。
- 新表需要标准 CRUD 时，继续读取 `AICoding/skills/be-vita-crud-generation/SKILL.md`。
- 交付时列出受影响模块和已执行的编译、测试；未执行的验证必须说明原因。
